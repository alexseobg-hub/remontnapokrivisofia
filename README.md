# remontnapokrivisofia.bg

Сайт за услуги в София. Съдържанието се пише в Notion, билдът произвежда статичен HTML.

## Как е устроено

Notion държи текста, кодът държи оформлението. При билд скриптовете вземат петте бази, свалят снимките локално и записват всичко в `src/data/content.generated.json`. React рендира страниците на сървъра, `prerender.js` ги изписва като готови HTML файлове. Браузърът получава пълна страница със заглавие, meta данни, canonical и JSON-LD, без да чака JavaScript.

```
Notion  →  fetch-notion-content.js  →  content.generated.json
                                              ↓
                        vite build (клиент) + vite build --ssr
                                              ↓
                             prerender.js  →  dist/  (статичен HTML)
```

## Старт

```bash
npm install
```

Копирайте `.env.example` в `.env` и попълнете `NOTION_API_KEY`. Останалите стойности вече сочат правилните бази.

```bash
npm run dev
```

Дърпа съдържанието от Notion и вдига сървър за разработка на http://localhost:5173.

## Билд

```bash
npm run build
```

Минава през четири стъпки: сваля съдържанието, билдва браузърния бъндъл, билдва сървърния и изписва статичните файлове в `dist/`. Генерира и `sitemap.xml`, `robots.txt` и `llms.txt`.

```bash
npm run preview
```

Вдига `dist/` на http://localhost:4180 с поведението на Vercel: чисти адреси, index в папка, 404.

## Notion

Всичко живее под страницата **Ремонт на покриви София — CMS**.

| База | За какво е |
|---|---|
| Страници | Всяка страница на сайта. `Slug` определя адреса, `Type` определя шаблона, само `Status = Published` влиза в билда. |
| Настройки | Телефон, ЕИК, адрес, гаранция. Кодът чете колоната `Key`, Вие пипате само `Стойност`. |
| Цени | Ценоразписът. Празна цена излиза на сайта като „По договаряне“. |
| Проекти | Реализирани обекти със снимки преди и след. |
| Отзиви | Истински отзиви. Празна база означава скрита секция. |

Интеграцията трябва да е свързана с родителската страница, не с всяка база поотделно. Свързването на родителя дава достъп до всичко под нея.

### Маркери в текста

Абзац, който съдържа само маркер, се заменя с компонент. Така текстът си остава текст в Notion, а оформлението идва от кода.

| Маркер | Какво вгражда |
|---|---|
| `[[trust]]` | Нищо. Ползите вече стоят на всяка страница над футъра. Маркерът се пази само за стари страници |
| `[[uslugi]]` | Мрежа с услуговите хъбове |
| `[[uslugi:/hidroizolaciya]]` | Подстраниците на конкретен хъб |
| `[[ceni]]` | Целият ценоразпис, групиран по категории |
| `[[ceni:chastichen,cyalosten]]` | Само избрани редове, по `Key` |
| `[[ceni:Улуци]]` | Само една категория |
| `[[proekti]]` | Мрежа с обектите |
| `[[proekti:Люлин]]` | Обектите в един квартал или по една услуга |
| `[[rayoni]]` | Списък с кварталите |
| `[[otzivi]]` | Отзивите. Празна база = нищо не се рендира |
| `[[proces]]` | Превръща **следващия номериран списък** в стъпки с едри числа |
| `[[karti]]` | Превръща **следващия списък с точки** в мрежа от карти |
| `[[kalkulator]]` | Калкулаторът за ориентировъчна стойност |
| `[[forma]]` | Формата за запитване |
| `[[kontakti]]` | Телефон, имейл, работно време, адрес |
| `[[karta]]` | Вградената карта |
| `[[garanciya]]` | Блокът с обхвата на гаранцията |
| `[[snimka:keremidi-pokriv]]` | Тематична снимка по ключ от `src/data/stock.json` |
| `[[ton:dark]]` | Кара текущата секция да е тъмна лента |

При `[[proces]]` и `[[karti]]` първите удебелени думи в реда стават заглавие на картата.

### Ленти

Всяко H2 в тялото отваря нова лента по цялата ширина. Тоновете се редуват сами: бяло, пясък, бяло. Две еднакви ленти не застават една до друга.

### FAQ

Секция с H2 „Често задавани въпроси“ се вади от текста и се рендира като акордеон. Всеки H3 е въпрос, всичко под него е отговорът. Оттам се генерира и `FAQPage` schema.

## Снимки

Заглавната част на всяка страница чете две полета от базата „Страници“.

- **Hero image** — ваша снимка, качена директно в Notion. Когато е попълнено, то бие.
- **Hero stock** — тематична снимка за начало, докато няма ваша.

Тематичните снимки са от Pexels. Лицензът позволява търговска употреба без посочване на автор. Произходът на всяка е записан в `src/data/stock.json`, а списъкът се поддържа в `scripts/prepare-stock.js`.

Те са само декоративни. Никоя не се показва като ваш реализиран обект. Картите в „Проекти“ приемат само истински снимки; докато няма такива, се рисува неутрален графичен блок.

За да се свалят или подменят:

```bash
node scripts/prepare-stock.js
```

## Плейсхолдъри

Полетата, които собственикът още не е попълнил, стоят като `{{NAME}}` в `src/config/site.ts`. Сайтът не ги показва на посетителя, а скрива секцията, която зависи от тях. В режим на разработка се виждат, за да се проследяват. Пълният списък и какво се очаква във всяко поле е в [PLACEHOLDERS.md](PLACEHOLDERS.md).

## Какво съзнателно липсва

`AggregateRating`, `Review` и `Offer` с конкретна цена не се генерират. Те изискват потвърдени данни; измислени оценки нарушават ЗЗП. Влизат в игра, когато има реални отзиви в Google.

Няма таймери за обратно броене и няма изкуствен недостиг. Няма лога на партньори без потвърдено разрешение. Няма сток снимки, представени като собствени обекти — когато няма истинска снимка, се рисува неутрален графичен блок.

## Запитванията

Формата праща на `/api/lead` — функция във Vercel, която живее в `api/lead.js`. Тя записва реда в базата **Запитвания** в Notion, със същия токен, с който се дърпа съдържанието. Няма втори доставчик и няма месечна такса.

Всяко запитване влиза със статус „Ново“. Оттам се мести през „Обадихме се“, „Оглед насрочен“, „Оферта дадена“ до „Спечелено“ или „Отпаднало“.

Функцията отхвърля запитване без име, с непълен телефон или без отметка за съгласие. Скритото поле `company` го пълнят само ботове — на тях се отговаря с успех, за да не опитват пак, но нищо не се записва.

Ако записът в Notion падне, посетителят вижда грешка и запитването не се брои за изпратено. По-добре видима грешка, отколкото мълчаливо изгубено обаждане.

### Писмо при всяко запитване

По желание. Празни полета значи, че редът в Notion е единственото копие.

| Променлива | За какво е |
|---|---|
| `RESEND_API_KEY` | Ключ от resend.com |
| `LEAD_EMAIL_TO` | Къде да идват писмата. Няколко адреса се делят със запетая |
| `LEAD_EMAIL_FROM` | Подателят. Домейнът трябва да е потвърден в Resend |

Ако писмото не тръгне, запитването пак е записано в Notion. Пощата е допълнение, не единственият изход.

`VITE_SITE_URL` решава и дали сайтът се индексира. Всеки адрес, различен от продукционния, дава `Disallow: /` в robots.txt и noindex по страниците. Затова, докато доменът не сочи към Vercel, оставете стойността празна или сложете адреса на самия preview — иначе временният `.vercel.app` влиза в Google преди истинския домейн.

## Обновяване от Notion

Съдържанието се дърпа по време на билда. Промяна в Notion не стига до сайта, докато не се пусне нов билд — Notion не уведомява никого.

Билд тръгва в три случая:

1. **При качване в GitHub.** Cloudflare следи клона `main`.
2. **По график.** Всяка сутрин в 04:30 UTC — 6:30 софийско през зимата, 7:30 през лятото. Настройва се в `.github/workflows/rebuild.yml`.
3. **На ръка.** GitHub → Actions → „Обновяване от Notion“ → Run workflow. Излиза за минута-две.

### Как се включва графикът

В Cloudflare Pages, в проекта: **Settings → Builds & deployments → Deploy hooks → Add deploy hook**. Име по избор, клон `main`. Cloudflare дава адрес.

Този адрес се записва в GitHub като тайна: **Settings → Secrets and variables → Actions → New repository secret**, име `CF_DEPLOY_HOOK`.

Адресът пуска билд на всеки, който го знае, затова стои като тайна, а не в кода.

### За лимита

Безплатният план на Cloudflare дава 500 билда месечно. Дневният график е 30. Останалото е за качвания и ръчни пускания — стига с голям запас.
